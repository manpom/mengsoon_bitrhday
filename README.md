### AI 그림 얹는 법 (표정 + 이동)

표정(`*_face_*.png`) 14장과 이동(`*_{down,up}_{idle,walk1,walk2}.png`) 12장이
전부 ChatGPT(유료 GPT 이미지) 로 교체됐습니다. 아직 절차적: `_lie`, `_nude_*`.

**소스: 전부 ChatGPT(유료 GPT 이미지).** 예전엔 Gemini(nano-banana) 로
뽑았는데, "배경 지워줘" 결과가 **알파가 아니라 체커보드가 픽셀에 구워진 불투명
PNG**로 받아지고, 프레임마다 확대율·다리 잘림이 제각각이라 GPT 로 전면 교체했습니다.

**이동 프레임의 특이점 (0-3 아래 표정 파이프라인과 대부분 동일):**
- 걷기 포즈는 3장짜리 스프라이트 시트로 한 번에 요청하면 3장이 다 똑같이
  나옵니다. **한 포즈씩** 따로 요청해야 다리를 제대로 듭니다.
- 방향(앞/뒤)마다 **idle + walk 딱 2장만** GPT 로 생성. `walk1` = walk 그대로,
  `walk2` = walk 를 좌우반전 (`integrate_ai_moves.ps1` 이 미러). 게임이 이동
  방향에 따라 또 flip 하지만 두 프레임이 미러라 L→모음→R→모음 사이클 성립.
- `up_*` 는 "뒤에서 본 모습, 얼굴 없음, 후드/리본 뒷면" 으로 요청.
- 첫 메시지에 앞선 캐릭터의 마젠타 컷을 레퍼런스로 같이 올려 **프레이밍 고정**.
- `integrate_ai_moves.ps1` 은 방향별로 **idle 의 캐릭터 키로 scale 을 한 번 정하고
  walk 에도 같은 scale** 을 씁니다 (프레임마다 크기가 맥동하면 안 됨). idle·walk
  모두 알파 bbox 바닥(딛는 발)을 `FOOT_Y` 에 맞춥니다.

**ChatGPT 파이프라인 (3단계 = 스크립트 2개):**

1. **생성** — 한 캐릭터당 대화 하나. 첫 메시지에 on-model 레퍼런스 이미지
   (맹순이 땐 상대 캐릭터의 마젠타 컷도 같이 올려 프레이밍 고정)와 **전 프레임
   공통 규칙**을 한 번에 박습니다:
   > 정면 전신, 두 발 다 보이고 바닥에 닿음 · 캐릭터 높이 = 이미지 높이의 ~70%,
   > 머리 위·발 아래 여백 넉넉 · 정중앙 · **평평한 단색 마젠타 #FF00FF 배경, 그라데이션·
   > 그림자·바닥선 없음** · 몸 포즈는 세트 내내 고정, 얼굴(+작은 손동작)만 바뀜.
   그 다음 `Image N - HAPPY: <눈·입 묘사>. 나머지는 image 1 과 완전히 동일.`
   식으로 7장. 마젠타는 캐릭터 색(올리브/하늘색/핑크)과 안 겹쳐 키잉이 쉽습니다.
   > ⚠️ ChatGPT 라이트박스의 **"배경 제거" 버튼은 쓰지 마세요.** 그건 이미지를
   > 다시 생성하면서 피사체로 확대-크롭해버려서 애써 맞춘 프레이밍이 다 깨집니다.
   > 마젠타 배경 그대로 다운로드해서 아래 스크립트로 우리가 직접 키잉합니다.
2. 마젠타 원본을 `tools/ai_refs/_gpt_raw/<who>_<expr>.png` 로 저장.
3. **키잉** — `tools/clean_ai_refs.ps1` 실행.

```bash
powershell -ExecutionPolicy Bypass -File tools\clean_ai_refs.ps1      # 마젠타 -> 투명 (표정+이동)
powershell -ExecutionPolicy Bypass -File tools\integrate_ai_faces.ps1  # 표정 -> 192x192
powershell -ExecutionPolicy Bypass -File tools\integrate_ai_moves.ps1  # 이동 -> 192x192
```

`clean_ai_refs.ps1` 은 무거운 픽셀 작업을 **C#(Add-Type)** 로 돌립니다 (PowerShell
루프로 150만 픽셀은 너무 느리고 정수 나눗셈이 반올림돼서 터짐). 가장자리에서
"마젠타다움"(R·B 높고 G 낮음) 이 임계 이상인 픽셀을 flood-fill 로 지우고 —
**테두리에서 시작하므로 안쪽 핑크 드레스·볼터치는 절대 안 건드림** — 남은
가장자리는 알파를 낮춰 페더링하고 마젠타 끼(디스필)를 뺍니다. 마지막에 제일 큰
연결 덩어리만 남깁니다.

`integrate_ai_faces.ps1` 은 `clean/face_*.png` 를 읽어 알파로 캐릭터를 찾고
192x192 프레임에 배치합니다 (발이 아래에서 2px, 키 176px 로 정규화 → 소스
해상도 무관). `$TwoPanel`/`$Skip` 은 지금 비어 있습니다 (예전 2패널 제미니
소스용). 캐릭터 덩어리가 캔버스를 거의 꽉 채우면(배경 안 지워짐) `!! 크기
이상해서 건너뜀` 을 찍고 절차적 그림을 그대로 둡니다.

> ⚠️ **`tools/integrate_ai_faces.ps1` 은 반드시 UTF-8 **BOM** 으로 저장하세요.**
> BOM 이 없으면 한글 Windows 의 PowerShell 5.1 이 cp949 로 읽어서, 한글 주석

## 0-4. 꼭 알아야 할 규칙 4개

### ① 해상도 — 480×270 → **960×540**

`project.godot` 에서 이미 바뀌어 있습니다.
```
window/size/viewport_width=960
window/size/viewport_height=540
window/stretch/mode="canvas_items"        ← viewport 아님. 도트가 아니라 확대해도 안 깨짐
textures/canvas_textures/default_texture_filter=1   ← 1 = Linear. Nearest 아님
```
**예전 씬의 좌표를 옮길 때는 전부 ×2 하면 됩니다.** 폰트 크기도 마찬가지입니다.

### ② 디오라마 투영식 — 방에 물건을 놓을 때

방은 **한 장의 그림**입니다. 가구를 따로따로 스프라이트로 쪼개지 않았습니다.
(쪼개면 물건끼리 드리우는 그림자와 가림이 깨져서 3D 느낌이 사라집니다.)
대신 **텍스처 없는 투명 `Prop` 노드**를 그림 위에 올려서 조사 범위로 씁니다.

새 물건의 씬 좌표는 그림과 똑같은 식으로 계산합니다:
```
sx = 30 + x + z * 0.18
sy = 648 - z * 0.54 - h
```
- `x` = 가로, `z` = 안쪽 깊이, `h` = 높이. 셋 다 `build_room_iso.ps1` 안의 값과 같은 단위
- 이 상수들은 `tools/_iso.ps1` 맨 위 `Set-Camera 648.0 0.54 0.18 30.0` 에서 옵니다.
  **카메라 값을 바꾸면 방 그림과 씬 좌표가 통째로 어긋납니다.** 바꾸지 마세요

### ③ 캐릭터 프레임 규칙 — 192×192, 발이 아래에서 2px 위

`Body.offset = Vector2(0, -96)` 이라서 **노드 위치 = 발밑**이 됩니다.
예전 도트(64×64 / offset −32)와 같은 규칙을 2배로 옮긴 것뿐입니다.

**예외 하나:** `lie`(누운 그림)는 서 있는 그림을 90도 돌린 것이라 이 규칙이 안 통합니다.
그래서 `scripts/levels/mengdol_house.gd` 의 `BED_POS` 는 눈으로 맞춘 값입니다.
> 알려진 미흡한 점: 침대는 3/4로 그려졌는데 누운 캐릭터만 납작해서 머리가 머리판에
> 살짝 겹칩니다. 나중에 **누운 전용 프레임**(머리는 베개, 몸은 발치로 물러나는 투영)을
> 따로 그리면 확실히 좋아집니다. 급하진 않습니다.

### ④ 미니게임 화면은 배경을 (-40, -100) 에 놓습니다

미니게임에는 카메라가 없습니다. 그래서 1280×660 짜리 배경 그림 중
**어디를 보여줄지를 스프라이트 위치로 정합니다.**

```
Bg.position = Vector2(-40, -100)      ← centered = false
```
그러면 기준 화면 960×540 안에 그림의 **x 40~1000, y 100~640** 이 들어옵니다.
캔버스를 화면보다 크게(1280) 잡아 둔 것은 아이폰(19.5:9)처럼 화면이 더 넓을 때
좌우로 배경이 계속 이어져 보이게 하기 위해서입니다. `expand` 스트레치가
좌우를 더 보여주는데, 거기가 흰 여백이면 그대로 티가 납니다.

캐릭터가 설 자리는 배경과 **같은 투영식**(②)으로 계산한 뒤 `-40, -100` 을 빼면 됩니다.
컷신의 두 사람은 x=364 / x=554, 둘 다 z=200 (발매트 위) 입니다.


## 0-5. PowerShell + System.Drawing 함정 모음 ★

작업하다 실제로 다 한 번씩 밟은 것들입니다. 같은 데서 또 막히지 마세요.

| 증상 | 원인 | 해결 |
|---|---|---|
| 팔레트 변수가 통째로 날아감 | **PowerShell 변수는 대소문자를 구분하지 않습니다.** `$K` 팔레트가 `foreach ($k in 0,1)` 에 덮어씌워짐 | 팔레트는 `$PAL` / `$C3` 처럼 긴 이름으로 |
| `op_Subtraction ... Object[]` | `@($a - $b*2, $c)` 에서 **쉼표가 산술보다 강하게 묶임** | 배열 원소마다 괄호: `@(($a - $b*2), $c)` |
| 인자 개수가 안 맞는다는 오류 | `New-Object Rectangle(0,$y,$w,[int]$h+1)` 에서 `+1` 이 **5번째 인자로 파싱** | 미리 변수에 계산해 두고 넘기기 |
| 뜬금없는 null 오류 10개 | `Foo (if ($a) { 1 } else { 2 })` — **인자 자리에 `if` 를 식으로 못 씀** | 위에서 변수로 계산 후 전달 |
| `AddArc` 예외 | `RoundRectPath` 반지름이 0 | `$r -le 0.5` 면 `AddRectangle` 로 분기 (이미 처리됨) |
| 얼굴 오른쪽 아래에 때 낀 자국 | `ShadeIn` 의 바닥 그늘이 볼에 얹힘 | 얼굴에는 `ShadeTopOnly` 사용 |
| 원기둥이 거대한 타원이 됨 | 가로로 눕힌 봉에 `Cyl3` 사용 (`Cyl3` 는 세로 전용) | 가로 물체는 `Box3` |
| 한글 주석 **다음 줄** 이 실행 안 됨 (변수에 이전 루프 잔여값이 남음) | `.ps1` 이 **BOM 없는 UTF-8** → PS 5.1(cp949)이 한글 3바이트를 오해해 줄바꿈을 삼킴. `integrate_ai_faces.ps1` 에서 중앙정렬 한 줄이 통째로 증발했음 | **UTF-8 BOM 으로 저장.** `(Get-Content).Length` 로 첫 3바이트 `EF BB BF` 확인 |

### Godot 쪽 함정

| 증상 | 원인 | 해결 |
|---|---|---|
| `Trying to assign invalid previously freed instance` | `var s: Sprite2D = n["node"]` — **`if` 검사 전에 대입에서 이미 터짐** | `done` / `is_instance_valid()` 를 **대입보다 먼저** 검사 |
| 터치 입력이 두 번 먹음 | `emulate_mouse_from_touch` 때문에 터치가 마우스로도 들어옴 | `InputEventMouseButton` **하나만** 처리. `InputEventScreenTouch` 는 받지 말 것 |
| 웹에서 소리가 안 남 | 브라우저 자동재생 정책 | 첫 탭을 기다리는 게이트 (`_wait_for_first_tap`, 이미 구현됨) |

## 0-6. 사용자가 확정한 지시사항 (되돌리지 마세요)

- **도트는 완전히 버린다.** "몽글몽글하고 포근한 느낌의 귀여운 2D 인디게임"
- **캐릭터 측면(옆모습) 뷰는 만들지 않는다.** 앞/뒤 + 좌우 반전만
- **액자는 전부 없앤다.** (나중에 다시 지시하겠다고 함)
- **글러브는 손목까지 전부 빨강. 이음선·바느질선 같은 잔선은 넣지 않는다.**
  벽 고리에 끈으로 매달아 놓은 실루엣이라야 글러브로 읽힙니다 (이거 찾는 데 7번 실패)
- **맹돌이는 이빨 없음.** 튀어나온 앞니는 맹꽁이 같고 특징도 아니라서 전부 뺐습니다
  (AI 세트 재생성 때 "NO teeth, 매끈한 입" 으로 못박음)
- **맹순이 앞니는 가운데로 모아 하나로.** 두 이빨 사이 경계선 없이, 윗입술 가운데서
  삐죽 나온 동그란 이빨 하나("buck-tooth")로. 콧구멍은 작게
- **문은 벽과 같은 선상에** (튀어나오면 안 됨)
- **미니게임 로직은 그대로.** 그림과 좌표만 바꾼다

## 2. Godot의 기본 개념 (Scene / Node / Autoload)

### Node (노드)
기능 한 조각.

| 노드 | 하는 일 |
|---|---|
| `Node2D` | 위치·회전만 가진 가장 기본 2D 노드. 폴더처럼도 씀 |
| `Sprite2D` | 이미지 한 장을 화면에 그림 |
| `AnimatedSprite2D` | 여러 장을 순서대로 넘겨서 애니메이션을 만듦 |
| `CharacterBody2D` | 코드로 직접 움직이는 물리 몸체 (플레이어·NPC용) |
| `StaticBody2D` | 움직이지 않고 막기만 하는 몸체 (벽·가구) |
| `CollisionShape2D` | 위 몸체들의 "실제 충돌 판정 모양" |
| `Area2D` | 부딪히진 않고 **겹쳤는지만** 감지 (조사 범위) |
| `Camera2D` | 화면을 어디를 비출지 결정 |
| `CanvasLayer` | 카메라가 움직여도 화면에 고정되는 UI 층 |
| `AudioStreamPlayer` | 소리 한 개를 재생 |

### Scene (씬)
**노드들을 부모-자식으로 조립해서 저장한 것**이 씬(`.tscn`)입니다.
씬은 다른 씬 안에 **부품처럼 끼워 넣을 수 있습니다**(인스턴스).

```
mengdol_house.tscn  (무대)
   ├─ mengdol.tscn  을 끼워 넣음      ← 플레이어
   └─ prop.tscn     을 7번 끼워 넣음  ← 침대 / 옷장 / 창문 / 문 / 책상 / 의자 / 글러브
```

### Autoload (자동 로드)
게임이 켜져 있는 내내 살아 있어서, **어느 씬에서든 이름으로 부를 수 있는 노드**입니다.
`project.godot` 의 `[autoload]` 에 등록돼 있습니다.

| 이름 | 하는 일 |
|---|---|
| `GameState` | 어디까지 진행했는지 · 사진 몇 장을 해금했는지 기억 (`set_flag()` / `unlock_photo()`) |
| `Dialogue` | 화면 아래 대사창. `Dialogue.say(["안녕"])` 한 줄로 어디서든 호출 |
| `DevCapture` | 개발용 스크린샷 도구. 평소엔 아무 일도 안 함 (10번 항목) |

## 4. 씬 구조 자세히

### `mengdol_house.tscn` — 맹돌이의 집 (게임 시작 씬)
```
MengdolHouse (Node2D)             ← mengdol_house.gd
├── Floor                         그림만. 항상 캐릭터보다 뒤에 그려짐
│   ├── Background                room_bg.png (640x330)
│   ├── Rug
│   ├── Frame1 ~ Frame5           ★ 빈 액자 5개 = 미니게임 5개 자리
│   ├── Window (Prop)             창문 (새벽 하늘)
│   ├── Door (Prop)               ★ 문 — 벽의 일부라서 여기 있습니다 (아래 설명)
│   └── Bed (Prop)                침대틀 + 매트리스 + 베개
├── Props            ★Y-Sort 켜짐  아래에 있는 것이 앞에 그려짐
│   ├── Quilt                     이불
│   ├── Wardrobe / Desk / Chair   (Prop)
│   └── Player                    mengdol.tscn
├── Walls                         방 밖으로 못 나가게 막는 사각형 4개
├── UI  (CanvasLayer 5)           조작 안내
└── Fx  (CanvasLayer 20)          암전용 검은 사각형 (대사창보다 위에)
```

> **왜 침대틀은 `Floor` 에 있고 이불만 `Props` 에 있나?**
> Y-Sort 는 "화면에서 아래에 있는 것을 앞에" 그립니다.
> 침대틀의 기준점(발치, y=272)은 자고 있는 맹돌이(y=255)보다 아래라서,
> 같이 정렬하면 **침대가 맹돌이를 덮어 버립니다.**
> 그래서 침대틀은 아예 뒤 레이어에 고정하고, **덮여야 하는 이불만** Y-Sort 에 넣었습니다.
> 이불 기준점(y=272) > 맹돌이(y=255) → 이불이 앞에 그려짐 → "이불 덮고 누워 있음".
> 침대에서 내려오면 맹돌이가 더 아래로 가므로 **자동으로** 앞에 서게 됩니다.

### `mengdol.tscn` — 플레이어
```

├── Shadow                        발밑 그림자
├── Body (AnimatedSprite2D)       앞/뒤 × 서기/걷기 + 표정 6종 + 누운 그림
├── CollisionShape2D              발밑 30x10 사각형 (몸 전체가 아니라 발밑만!)
├── Interactor (Area2D)           반지름 30 원. 주변 물건 감지

```

> **왜 충돌 판정이 발밑만인가?**
> 위에서 내려다보는 시점에서는 "바닥에 발이 닿는 면적"만 막으면 자연스럽습니다.

## 5. 맹돌이 그림 (앞·뒤 / 걷기 / 표정)

> ⚠️ **이 아래 설명 중 "만드는 방법" 부분은 예전 도트 시절 것입니다.**
> 프레임 이름·표정 종류·연출 의도는 지금도 그대로 맞습니다. 다만 만드는 도구는
> `build64.ps1` / `build_char.ps1`(도트) 이 아니라 **`build_char_soft.ps1`** 이고,
> 크기는 64×64 가 아니라 **192×192**, `offset` 은 −32 가 아니라 **−96** 입니다.
> 0-3 · 0-4 를 먼저 보세요.

한 명당 **26장**이 자동으로 만들어집니다.

| 파일 | 내용 |
|---|---|
| `mengdol_down_idle/walk1/walk2` | 앞모습 (우리 쪽을 봄) |
| `mengdol_up_idle/walk1/walk2` | **뒷모습** (위로 걸어갈 때) |
| `mengdol_face_happy` | 😊 눈을 ^^ 로 감고 웃음 |
| `mengdol_face_surprise` | 😲 눈 커지고 입이 동그래짐 |
| `mengdol_face_sad` | 😢 눈꺼풀이 처지고 눈물 한 방울 |
| `mengdol_face_angry` | 😠 눈썹이 안쪽으로 내려감 |
| `mengdol_face_sleepy` | 😪 반쯤 감긴 눈 |
| `mengdol_face_shy` | 😳 눈을 내리감고 얼굴이 벌겋게 달아오름 |
| `mengdol_lie` | 침대에 누운 그림 (옆얼굴 + 어깨. 오프닝 전용) |
| `mengdol_nude_*` | 욕실 컷신 · 리듬 파트용 11장 — 8장 참고 |

> **옆모습(`side`)은 없앴습니다.**
> 앞얼굴에서 옆얼굴로 도는 게 이 디자인에서는 아무리 그려도 어색했습니다.
> 머리가 눈두덩 두 개와 턱뿐이라 옆으로 돌리는 순간 다른 동물이 되어 버립니다.
> 지금은 좌우로 걸어도 **앞모습을 쓰고 가는 쪽으로만 좌우반전**합니다.
> 2D 게임에서 아주 흔한 방식이고, 실제로 이쪽이 훨씬 자연스럽습니다.

> **`_lie` 는 앞얼굴을 90도 돌린 것입니다.**
> 침대는 옆에서 본 모습이라 머리맡이 왼쪽, 발치가 오른쪽입니다. 등을 대고
> 누우면 정수리가 왼쪽, 턱이 오른쪽을 향하고 **얼굴은 천장(=화면 위)을**
> 봅니다. 그래서 앞얼굴을 그린 뒤 `Rotate-CCW` 로 반시계 90도 돌립니다.
> **눈 두 개가 위아래로 나란히 놓이는 게 정상입니다.**
>
> 돌리지 않고 앞얼굴을 그대로 얹으면 "누운 게 아니라 서 있는 얼굴을 침대에
> 올려놓은" 그림이 됩니다.
>
> 돌리면 머리가 34x48 로 **세로로 길어지므로** 침대도 같이 커져야 합니다.
> 그래서 `bed_base` 는 132x66 → **156x104**, 매트리스 두께는 24 → **52px**
> 입니다. (옆에서 본 침대에 위에서 본 사람을 눕히는 건 RPG 의 흔한 눈속임인데,
> 매트리스가 사람을 담을 만큼 두꺼워야 안 들킵니다)

> **`shy` 홍조는 밑칠이 아니라 좌표로 색을 고릅니다.**
> 머리의 밑칠은 좌우 대칭이 아닙니다 — `Draw-Head` 가 오른쪽 1/4 을
> 크림색(`c`)으로 덮어 턱 그늘을 만들기 때문입니다. 그래서 "지금 무슨
> 색인지 보고 칠할 색을 고르면" 왼쪽은 빨강, **오른쪽만 주황**이 되어
> 한쪽이 옅어 보입니다.
> 지금은 "입선 아래 + 턱 타원 안이면 턱, 아니면 얼굴"로 **좌표만 보고**
> 정하고, 왼쪽 절반만 계산해서 x 를 뒤집어 복사합니다. 좌표는 좌우가
> 완전히 같으므로 결과도 반드시 대칭입니다.

```bash
powershell -ExecutionPolicy Bypass -File tools\build_char.ps1
```
→ `assets/sprites/characters/mengdol/` · `mengsoon/` 에 굽고
   `tools/char_preview.png` 로 52장을 한 장에 모아 보여 줍니다.

### 걷기는 어떻게 굴러가나
`mengdol.tscn` 의 `Body` 노드 안에 애니메이션이 등록돼 있습니다.
걷기는 **walk1 → 서기 → walk2 → 서기** 4프레임을 초당 9장으로 돌립니다.
`mengdol.gd` 가 속도를 보고 방향을 정합니다.

```gdscript
if absf(velocity.x) > absf(velocity.y):
    _facing = "down";  body.flip_h = velocity.x < 0.0   # 좌우는 앞모습을 뒤집어서
else:
    _facing = "down" if velocity.y > 0.0 else "up"
```

**발소리**는 "발을 딛는 프레임(0번·2번)"으로 넘어갈 때마다 납니다.
그림과 소리가 저절로 맞으므로 따로 타이머를 돌릴 필요가 없습니다.

### 표정 쓰는 법
```gdscript
player.show_face("surprise")   # happy / surprise / sad / angry / sleepy
await get_tree().create_timer(1.0).timeout
player.show_face("")           # 원래 얼굴로
```
표정을 짓고 있는 동안에는 걸어도 그림이 안 바뀝니다(컷신용).

### 그림을 고치고 싶으면
`tools/build64.ps1` 이 캐릭터 한 장을 그립니다. 옵션이 넷입니다.

```bash
powershell -ExecutionPolicy Bypass -File tools\build64.ps1 -Who mengdol -Dir up -Step 1 -Face angry
```

| 옵션 | 값 |
|---|---|
| `-Who` | `mengdol` / `mengsoon` |
| `-Dir` | `down` 앞 / `up` 뒤 |
| `-Step` | `0` 서기 / `1` 왼발 듦 / `-1` 오른발 듦 |
| `-Face` | `normal` / `happy` / `surprise` / `sad` / `angry` / `sleepy` / `shy` / `laugh` |
| `-Pose` | `stand` / `guard` / `punch1` / `punch2` / `laugh` / `fart` / `lie` |
| `-Nude` | 옷을 벗김 (욕실 컷신 · 리듬 파트용) |
| `-Variant` | 얼굴 세부안 0~5 (현재 맹돌이 0, 맹순이 2) |

각 부위를 따로 그린 뒤 **부위마다 1px 외곽선을 두르고 겹쳐 쌓는** 방식이라,
머리가 몸 위에 올라가도 턱선이 뭉개지지 않습니다.

> **감은 눈은 반드시 `EyeArc` 로 그립니다.**
> 예전에는 열마다 `Round(중심 + |dx| * 기울기)` 를 찍었는데, 그러면 눈이
> **점선**으로 나옵니다. 이유가 두 개입니다.
>
> 1. 눈 중심이 `.5` 자리(눈두덩 한가운데)라서, `[math]::Round` 의
>    **은행가 반올림**이 같은 x 를 두 번 찍고 그 다음 x 는 건너뜁니다.
>    → `EyeArc` 는 오프셋이 아니라 **정수 x 를 직접** 훑습니다.
> 2. y 도 한 번에 1픽셀씩 뛰므로 두께 2px 로는 칸을 못 건넙니다.
>    → 각 열을 **바로 앞 열까지 이어서** 칠합니다.
>
> 이 두 가지를 안 하면 웃는 눈이 바코드처럼 보입니다.
| y | 부위 |
|---|---|
| 1~33 | 머리 (눈두덩 2개 + 크림색 턱) |
| 34~49 | 후드티 |
| 50~55 | 반바지(맹돌이) / 치마(맹순이) |
| 56~58 | 다리 |
| 59~63 | 신발 |

색은 `tools/art/_palette.txt` 에서 `글자 RRGGBB` 한 줄로 정의합니다.

> **PowerShell 함정**: 함수 이름을 `R`, `E`, `C`, `Erase`, `Clear` 로 짓지 마세요.
> PowerShell은 함수보다 **별칭(alias)을 먼저** 찾기 때문에
> `Invoke-History` / `Remove-Item` / `Clear-Host` 가 대신 불립니다.
> (그래서 이름이 `Fill` / `Oval` / `Hex` / `Punch` 입니다.)

## 6. 오프닝은 어떻게 흘러가나

`scripts/levels/mengdol_house.gd` 의 `_play_intro()` 하나만 보면 됩니다.

```gdscript
await _fade_to(0.55, 0.50)      # 눈을 반쯤 뜬다
await _fade_to(1.00, 0.22)      # 다시 감는다
await _fade_to(0.30, 0.45)      # 더 뜬다
await _fade_to(0.85, 0.20)      # 또 감는다
await _fade_to(0.00, 0.80)      # 완전히 뜬다

Dialogue.say(LINES_WAKE)        # (으음...) (여기가... 어디지?)
await Dialogue.finished

await _get_out_of_bed()         # 침대에서 내려온다 + 카메라가 뒤로 빠진다

Dialogue.say(LINES_OUT_OF_BED)  # (내 집인가...?) ...
await Dialogue.finished

_begin_play()                   # 조작권을 넘긴다
```

`await` 는 **"이게 끝날 때까지 기다렸다가 다음 줄"** 이라는 뜻입니다.
컷신 쓸 때 제일 편한 문법이라, 앞으로 다른 장면도 이 모양으로 쓰면 됩니다.

대사는 같은 파일 위쪽의 `LINES_WAKE` / `LINES_OUT_OF_BED` 만 고치면 됩니다.

**컷신 동안 조작이 잠기는 방식**: `player.control_enabled = false` 로 두면
`_physics_process` 자체가 꺼집니다. `move_and_slide()` 가 아예 안 돌아가므로,
맹돌이가 침대(=막힌 영역) 안에 서 있어도 물리에 밀려 튀어나오지 않습니다.

**침대에 누워 있는 동안**에는 서 있는 그림 대신 `mengdol_lie` 로 고정합니다.
안 그러면 이불 위에 사람이 서 있는 것처럼 보입니다. 발밑 그림자도 같이 끕니다.

```gdscript
player.lock_anim("lie")          # 누운 그림으로 고정
player.shadow.visible = false
...
player.lock_anim("")             # 풀기 (다시 걷기/서기 그림으로)
player.shadow.visible = true
```

침대는 **옆에서 본 모습**이라 침대틀은 `Floor` 에, 이불만 `Props`(Y-Sort) 에
있습니다. 이불 기준점이 누워 있는 맹돌이보다 아래라서 이불이 앞에 그려지고,
침대에서 내려오면 맹돌이가 더 아래로 가므로 자동으로 이불 앞에 서게 됩니다.

## 7. 물건 · 느낌표 · 미니게임 연결

### 하얀 느낌표 / 노란 느낌표
```
prompt.png        하양  = 그냥 둘러보는 물건. 대사만 나옴.
prompt_story.png  노랑  = ★ 조사하면 이야기가 진행되는 물건.
                          여기가 미니게임이 시작될 자리입니다.
```
`Prop` 의 `marker_kind` 를 `STORY` 로 두면 노란 느낌표가 붙고,
조사하는 순간 `story_triggered` 신호가 나갑니다.
지금은 **복싱 글러브**가 노란 느낌표입니다(= 추억 1 「원 투 뿡!」).

레벨 스크립트가 이걸 한 군데에서 받고, **물건 이름 → 미니게임 씬** 표를 봅니다.

```gdscript
## mengdol_house.gd
const MINIGAMES := {
    "Gloves": "res://scenes/minigames/one_two_bboong.tscn",
}

func _on_story_triggered(prop: Node) -> void:
    await Dialogue.finished
    GameState.set_flag("story_" + prop.name, true)
    var scene: String = MINIGAMES.get(prop.name, "")
    if scene.is_empty():
        return
    player.control_enabled = false
    await _fade_to(1.0, 0.7)          # 항상 암전을 한 번 거칩니다
    get_tree().change_scene_to_file(scene)
```

미니게임을 하나 더 붙일 때는 **`MINIGAMES` 에 한 줄 추가**하고 그 물건의
`marker_kind` 를 `STORY` 로 바꾸면 끝입니다. 액자가 5개니까 이 표도 결국 5줄이 됩니다.

돌아올 때는 미니게임 쪽에서 `change_scene_to_file("res://scenes/levels/mengdol_house.tscn")`
을 부르면 됩니다. 방은 `intro_done` 플래그를 보고 오프닝을 건너뛴 뒤,
까만 화면에서 0.7초에 걸쳐 밝아집니다(미니게임이 암전으로 끝나므로 그대로 이어집니다).
### 물건을 하나 더 놓고 싶다면
에디터에서 `Props`(또는 `Floor`) 밑에 `scenes/objects/prop.tscn` 을 끌어다 놓고,
인스펙터에서 값만 채우면 끝입니다.

| 항목 | 뜻 |
|---|---|
| `texture` | 그림. **아래쪽 한가운데**가 노드 position 에 오도록 자동 배치 |
| `sprite_bottom_pad` | PNG 아래에 들어 있는 그림자 여백 (기본 6, 아래 설명) |
| `marker_kind` | `LOOK` 하양 / `STORY` 노랑 |
| `solid_size` / `solid_offset` | 못 지나가게 막을 사각형. `(0,0)` 이면 통과 가능 |
| `zone_size` / `zone_offset` | 이 안에 들어오면 조사 가능. `(0,0)` 이면 조사 불가 |
| `lines` | 조사했을 때 나올 대사. **한 줄 = 대사창 한 번** |
| `marker_offset` | 느낌표가 뜰 위치 |

> **기준점 규칙**: 모든 물건의 `position` 은 **바닥에 닿는 지점**입니다.
> `solid_offset` · `zone_offset` · `marker_offset` 은 전부 그 지점에서 잰 값이라
> 물건을 통째로 옮겨도 세 개가 같이 따라옵니다.

> **느낌표가 화면 위로 잘리는 문제**: 카메라는 방 밖을 안 비추기 때문에,
> 플레이어가 방 아래쪽에 있을 때 화면 맨 위는 대략 `y=60` 입니다.
> `marker_offset` 은 **월드 y 가 65 아래로 오도록** 잡아야 안 잘립니다.

## 8. 미니게임 1 「원 투 뿡!」 (추억 1 · 원투 방구 사건)

방 안의 **복싱 글러브**를 조사하면 암전 → 이 미니게임으로 넘어옵니다.
씬이 둘입니다. 컷신이 암전으로 끝나고 리듬 파트가 암전에서 시작하므로 그대로 이어집니다.

| 씬 | 스크립트 | 무엇 |
|---|---|---|
| `one_two_bboong.tscn` | `one_two_bboong.gd` | 욕실 도입 컷신 |
| `one_two_rhythm.tscn` | `one_two_rhythm.gd` | 리듬 파트 (32초) |

### 8-1. 도입 컷신

깔끔한 욕실(`assets/sprites/stages/bath_bg.png`)에 둘이 나란히 서 있고,
옷을 안 입은 상태입니다.

```
페이드인
  맹돌 "...어때, 이제 복싱에 대해 조금 알겠어?"
  맹순 "조금 어려워. 직접 보여줄 수 있어?"
  맹돌 "당연하지. 잘 보고 따라해봐."
  맹돌이 자세 → 왼손 "원!" → 오른손 "투!"
  맹돌 "따라해봐."
  맹순이 자세 → 왼손 "원!" → 오른손 "투!" → 뿡!   (보라색 방귀 3단계)
  맹순이 얼굴이 벌겋게 달아오름 (nude_shy)
  맹돌이 배꼽 잡고 눈물나게 웃음 (nude_laugh)
페이드아웃 → one_two_rhythm.tscn
```

### 8-2. 리듬 파트

맹돌이가 가운데에서 **내내 눈물 흘리며 웃고** 있고, 맹순이는 뒤에서 보고 있습니다.
맹돌이 둘레 세 군데에 판정 링이 있고, 노트가 위에서 떨어집니다.

```
            [뿡]  스페이스
              ○  (480, 192)

  [원] ←                          → [투]
   ○ (220,352)     맹돌이      ○ (740,352)
```

| 레인 | 노트 그림 | 키 | 맞히면 |
|---|---|---|---|
| 왼쪽 | `note_glove.png` | **←** (또는 A) | 맹돌이가 **"원"** (왼손 잽) |
| 위 | `note_face.png` (맹순이의 부끄러운 얼굴) | **스페이스** (또는 ↑) | 맹돌이가 **"뿡"** + 보라색 구름 |
| 오른쪽 | `note_glove.png` | **→** (또는 D) | 맹돌이가 **"투"** (오른손 잽) |

아이폰에는 키보드가 없으므로 **화면을 세로로 삼등분**해서 씁니다.
왼쪽 36% = 원, 오른쪽 36% = 투, 가운데 = 뿡. (`_lane_at()`)

> **왜 버튼 하나가 아니라 셋인가**
> 처음에는 리듬천국처럼 버튼 하나로 만들었습니다. 그런데 버튼이 하나면
> **같은 박에 노트를 두 개 놓을 수가 없습니다.** 어느 쪽을 친 것인지 구별할
> 방법이 없기 때문입니다.
> 키를 셋으로 나누니 "← 와 → 를 거의 동시에" 같은 리듬이 가능해졌고,
> 그게 이 게임에서 제일 재미있는 구간이 됩니다 (채보의 ★ 표시 마디).
> 대신 각 키는 **자기 레인만** 봅니다 — 왼쪽을 눌렀는데 위 노트가 사라지는
> 일은 없습니다 (`_hit_lane()`).

입력은 `project.godot` 의 `[input]` 에 있는 세 액션을 씁니다.
키를 바꾸고 싶으면 Godot 에디터의 **프로젝트 → 프로젝트 설정 → 입력 맵**에서
`lane_left` / `lane_up` / `lane_right` 를 고치면 됩니다.

#### 판정

정박에서 얼마나 벗어났는지로만 나눕니다. 가까울수록 좋습니다.

| 등급 | 창 | 점수 |
|---|---|---|
| `GREAT!` | ±0.052초 | 100 |
| `GOOD` | ±0.105초 | 60 |
| `COOL` | ±0.175초 | 30 |
| `MISS` | 그 밖 | 0, 콤보 끊김 |

맞으면 노트가 **조금 커지면서 흐려지고**, 링이 한 번 번쩍이고, 판정 글자가
튀어오릅니다. 허공에 눌러도 감점은 없습니다 (그것까지 잡으면 너무 맵습니다).

```bash
powershell -ExecutionPolicy Bypass -File tools\build_bgm.ps1
```

이 스크립트 하나가 **둘 다** 굽습니다.

- `assets/audio/bgm/one_two_bboong.wav` — 120 BPM · 16마디 · 32초
- `scripts/minigames/one_two_chart.gd` — 그 곡의 채보 (★ 자동 생성. 직접 고치지 마세요)

채보를 바꾸려면 `build_bgm.ps1` 안의 **`$BARS` 표** 한 군데만 고치고 다시
실행하면 됩니다. 음악의 멜로디도 그 표를 보고 만들어지므로, 노트가 있는
자리에서 정확히 소리가 납니다. 눈을 감고 들어도 원-투-뿡 박자가 들립니다
(리듬천국의 "귀로 치는" 설계). 둘을 따로 관리하면 반드시 어긋납니다.

`$BARS` 는 마디마다 `@(박, 레인)` 목록입니다.

```powershell
@(@(0.0, 'L'), @(1.0, 'R'), @(2.0, 'U')),   # 원 투 뿡
```

난이도는 **보통**입니다. 대부분 한 마디에 3~4개(원 투 뿡)이고,
8·11마디에서 8분음표로 몰아치며, ★ 표시한 6·9·12·14·15마디에서
같은 박에 두 개를 같이 눌러야 합니다.

> **박자는 프레임이 아니라 음악에서 읽습니다.**
> `_song_time()` 이 `get_playback_position()` 에 `get_time_since_last_mix()` 를
> 더하고 `get_output_latency()` 를 뺍니다. 이걸 안 하면 소리보다 그림이
> 몇 십 ms 앞서 보여서, 정확히 쳐도 계속 빠르다고 나옵니다.

> **해제된 노트를 만지지 마세요.**
> 맞은 노트는 트윈이 끝나면 `queue_free()` 됩니다. 그 뒤에
> `var s: Sprite2D = n["node"]` 를 하면 **대입 그 자체에서** 에러가 납니다
> (`if` 문까지 가지도 못합니다). 그래서 `_move_notes()` 는 `done` 과
> `is_instance_valid()` 를 **먼저** 확인합니다.

> **방귀 구름이 "방귀"로 보이게 하는 세 가지** (`build_stage1.ps1`)
> 1. 크기가 다른 동그라미 여섯 개를 겹친 **울퉁불퉁한 뭉게구름**
> 2. 나온 자리(오른쪽 아래 = 똥꼬)로 이어지는 **꼬리**.
>    말풍선 꼬리처럼 점점 가늘어지는 동그라미 세 개입니다.
> 3. 전체를 한 번에 두르는 **1px 외곽선**(`Edge`). 이게 없으면 겹친
>    동그라미로만 보이고, 만화 그림이 되지 않습니다.
>
> 밝은 면은 덩어리마다 따로 칠하지 않습니다. 같은 모양을 조금 작게,
> 왼쪽 위로 밀어서 한 번에 덮습니다 — 덩어리마다 밝게 칠하면 구름이
> 아니라 동그라미 여러 개로 보입니다.
>
> 씬 쪽 `_puff()` 의 위치 보정값은 **꼬리 끝이 엉덩이에 닿도록** 맞춘
> 값입니다. 구름 크기를 바꾸면 이 값도 같이 손봐야 합니다.

## 9. 그림자와 명암

가구가 바닥에 떠 있어 보이지 않도록 **PNG 안에 접지 그림자를 같이 구워 둡니다.**
`build_room.ps1` 의 `Start-Prop` 이 캔버스를 좌우 4px, 아래 `$SHADOW_PAD`(=6)px
넓혀 놓고 거기에 타원 그림자를 먼저 깔아 줍니다.

```
   ┌──────────────┐  ← 캔버스 (물건보다 좌우 4px, 아래 6px 큼)
   │  ┌────────┐  │
   │  │  옷장  │  │
   │  └────────┘  │
   │   ~~~~~~~~   │  ← 그림자
   └──────────────┘
              ↑ PNG 의 진짜 아래끝
        ↑ 여기가 "바닥에 닿는 지점" = 노드 position
```

★ 그래서 **`prop.gd` 의 `sprite_bottom_pad` 와 `build_room.ps1` 의 `$SHADOW_PAD`
는 항상 같은 숫자여야 합니다.** 한쪽만 바꾸면 가구가 위아래로 어긋납니다.

벽에 **걸리는** 것(창문·액자)은 바닥 그림자 대신 `Start-Wall` 이 오른쪽 아래로
살짝 밀린 그림자를 그려서 벽에서 떠 있는 느낌을 냅니다.

**문은 다릅니다.** 문은 벽에 걸린 게 아니라 **벽에 뚫린 구멍**이라서,
그림자가 있으면 "벽 앞에 세워둔 판자"처럼 보입니다. 그래서 문만 세 가지가 다릅니다.

| | 문 | 옷장 같은 가구 |
|---|---|---|
| 그리는 함수 | `Start-Flat` (그림자 없음) | `Start-Prop` (접지 그림자) |
| 씬에서 어디에 | `Floor` (벽의 일부) | `Props` (Y-Sort 대상) |
| 세로 위치 | 아래끝이 **벽/바닥 경계선(y=152)** 에 딱 맞음 | 바닥 위에 섬 |
| 막기 | 없음 (방 위쪽 벽이 이미 막음) | 발치에 `solid_size` |

대신 문틀 **안쪽** 위·왼쪽에만 그늘을 넣어서 "벽에 움푹 들어간" 느낌을 냅니다.

캐릭터는 별도의 `shadow.png` 를 발밑에 깔고, 몸 자체의 명암은
`build64.ps1` 이 "위는 밝게(`L`) / 오른쪽과 턱 밑은 어둡게(`v`)" 칠합니다.

> 2. 떨림이 **규칙적이면 안 됩니다.** 사인파 하나로 흔들면 부저가 됩니다.

> 3. 소리가 끊겼다 이어집니다(부르르). 진폭을 0 가까이 떨어뜨렸다 올립니다.
> 4. 저역만 두 번 거른 잡음(바람)이 깔려 있고, 끝에서 pffft 하고 빠집니다.

## 14. 방 배경과 가구 고치기 ★

```bash
powershell -ExecutionPolicy Bypass -File tools\build_room_iso.ps1
```

방은 **가구까지 통째로 그려진 한 장의 그림**(`room_iso.png`, 1280×660)입니다.
가구를 개별 스프라이트로 쪼개지 않은 이유는, 디오라마는 **물건끼리 드리우는 그림자와
서로 가리는 관계**로 입체감이 생기는데 쪼개면 그게 전부 깨지기 때문입니다.

예외가 하나 있습니다. **이불(`quilt_overlay.png`)만 따로** 나옵니다.
캐릭터보다 앞에 그려져야 "이불을 덮고 누워 있는" 것처럼 보이기 때문입니다.

### 그리는 방법

`tools/build_room_iso.ps1` 맨 위에 팔레트 `$C3`, 아래에 물건별 블록이 있습니다.
좌표는 **3D**(`x` 가로 / `z` 깊이 / `h` 높이)로 적고 `_iso.ps1` 이 화면 좌표로 바꿉니다.

| 함수 | 쓰임 |
|---|---|
| `Box3 x0 z0 x1 z1 h0 h1 윗면 앞면 옆면` | 상자 하나. **책상·침대·옷장·서랍 전부 이걸로** |
| `Cyl3 cx cz r h0 h1 윗면 앞면 옆면` | **세로로 선** 원기둥 (컵, 화분, 다리). 가로 물체에 쓰면 거대한 타원이 됩니다 |
| `FaceTop` / `FaceFront` / `FaceSide` | 면 하나만 직접 |
| `Contact x z rx ry` | 물건이 바닥에 닿는 자리의 짙은 그림자. **이게 없으면 물건이 떠 보입니다** |
| `CastShadow x0 z0 x1 z1 h` | 창 쪽 빛을 받아 앞으로 길게 드리우는 그림자 |
| `CornerDark` | 방 구석이 어두워지는 효과 |

**면마다 다른 밝기를 칠하는 것**(윗면 밝게 / 앞면 중간 / 옆면 어둡게)이
젤다·알바 같은 입체감의 정체입니다. 그러데이션이 아니라 **면 단위 단색**입니다.

### 조사할 수 있는 물건 추가하기

그림에 물건을 그린 다음, `mengdol_house.tscn` 의 `Zones` 밑에 **텍스처 없는 Prop**을
같은 자리에 놓습니다. 좌표는 0-4 의 투영식으로 계산합니다.

확인용 미리보기 `tools/room_iso_preview.png` 도 같이 나옵니다.
(미리보기에만 틸트시프트 흐림이 들어갑니다. 게임 배경에는 안 들어갑니다 —
카메라가 움직이면 흐린 띠가 같이 따라다녀서 어색하기 때문입니다.)

## 15. 알아둘 점 / 다음 단계

### 한글 폰트 — ✅ 해결됨
**Galmuri11** (https://github.com/quiple/galmuri, SIL Open Font License 1.1) 을
`assets/fonts/` 에 넣어 두었습니다. 폰트 파일이 프로젝트 안에 있으므로
**웹으로 내보내도 글자가 깨지지 않습니다.**

> ★ **글자 크기는 11 의 배수로 쓰세요.** Galmuri11 은 11픽셀에 딱 맞게 그려진
> 폰트라, 12나 13으로 쓰면 미묘하게 뭉개집니다. 크게 쓰려면 22, 33 으로.
> 안티에일리어싱·힌팅은 `assets/fonts/*.ttf.import` 에서 이미 꺼 두었습니다.
> `OFL.txt` 는 라이선스 조건이라 **지우면 안 됩니다.**

### 아이폰 대비
웹으로 내보내는 이야기는 **16장에 따로 정리했습니다.** 여기서는 요약만.

- ✅ 렌더러 `gl_compatibility` · 텍스처 필터 `Linear` · 스트레치 `canvas_items`+`expand` (960×540)
- ✅ 폰트를 파일로 포함 (시스템 폰트를 빌려 쓰면 웹에서 한글이 깨집니다)
- ✅ 터치 조작 — 찍은 곳으로 걸어가기 + 물건 찍으면 자동 조사,
  리듬 게임은 화면 좌/중/우 삼등분
- ✅ 시작 전 탭 한 번을 받아 브라우저 오디오를 깨웁니다
- ⚠️ 안 쓰는 폰트 2개(7.3MB)를 내보내기에서 빼야 합니다 (16장)
- ⚠️ 내보내기 프리셋에서 **Thread Support 를 꺼야** 정적 호스팅에서 돌아갑니다 (16장)

> 아직 안 해 본 것: **실제 아이폰에서 돌려보기.** 웹 내보내기를 한 번 해서
> 폰트·터치·프레임·소리를 실기로 확인해 보는 게 좋습니다.

## 16. 아이폰 웹으로 내보내기 ★

앱이 아니라 **웹페이지**로 돌립니다. 사파리에서 주소만 열면 되는 방식입니다.

### 이미 맞춰 둔 것

| 항목 | 값 | 왜 |
|---|---|---|
| 렌더러 | `gl_compatibility` | 웹은 WebGL2 로 돌아갑니다. Forward+ 를 고르면 아이폰에서 아예 안 켜집니다 |
| 텍스처 필터 | `Linear` | 도트가 아니라 부드러운 일러스트라 확대해도 매끈해야 합니다 |
| 화면 늘리기 | `canvas_items` + `expand` | 아이폰은 19.5:9 라 기준(16:9)보다 넓습니다. `expand` 면 좌우를 더 보여 줍니다 |
| 폰트 | 파일로 포함 | 시스템 폰트를 빌려 쓰면 웹에서 한글이 깨집니다 |
| 터치 | 마우스 이벤트만 처리 | 아래 설명 |
| 첫 소리 | 시작 전 탭 한 번 | 아래 설명 |

### 내보낼 때 반드시 확인할 것

Godot 에디터 → **프로젝트 → 내보내기 → 추가 → 웹**

1. **`Variant / Thread Support` 를 끕니다.**
   켜면 브라우저가 `SharedArrayBuffer` 를 쓰는데, 그러려면 서버가
   `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` 헤더를
   보내 줘야 합니다. GitHub Pages 같은 정적 호스팅은 그 헤더를 못 넣습니다.
   끄면 그냥 올려도 돌아갑니다.
2. `Extensions Support` 도 끕니다 (GDExtension 을 안 씁니다).
3. 내보낸 폴더를 통째로 정적 호스팅에 올립니다.
   GitHub Pages · Netlify · itch.io 다 됩니다. `.wasm` 을 올바른 MIME 으로
   주기만 하면 되는데, 셋 다 알아서 해 줍니다.

### 용량 — 지금 제일 큰 문제

`assets/fonts/` 가 **13MB** 인데 실제로 쓰는 건 `Galmuri11.ttf` 하나뿐입니다.

| 파일 | 크기 | 쓰나 |
|---|---|---|
| `Galmuri11.ttf` | 5.4MB | ✅ 테마 기본 폰트 |
| `Galmuri11-Bold.ttf` | 2.6MB | ❌ 아무 데서도 안 씀 |
| `Galmuri9.ttf` | 4.6MB | ❌ 아무 데서도 안 씀 |

**안 쓰는 두 개를 빼면 7.3MB가 그대로 줄어듭니다.** 셀룰러로 처음 여는
사람에게는 체감이 큽니다. 지우거나, 내보내기 프리셋의
**리소스 → 내보낼 리소스 선택** 에서 제외하세요.
(나중에 굵은 글씨가 필요해지면 다시 넣으면 됩니다)

음악 `one_two_bboong.wav` 는 1.4MB 입니다. 더 줄이고 싶으면
`build_bgm.ps1` 의 `$RATE` 를 11025 로 낮추면 절반이 됩니다(음질은 떨어집니다).

### 웹에서만 생기는 함정 두 가지

> **① 브라우저는 사용자가 화면을 건드리기 전까지 소리를 안 냅니다.**
> 자동 재생 정책이라 아이폰만의 문제가 아닙니다. 오프닝은 켜자마자 글자
> 소리가 나므로, 그냥 두면 첫 두어 줄이 무음으로 지나갑니다.
> 그래서 시작 화면에 **"화면을 탭하거나 아무 키나 누르세요"** 를 띄우고
> 입력을 한 번 받습니다 (`mengdol_house.gd` 의 `_wait_for_first_tap()`).
> 이 한 번의 입력이 오디오를 깨웁니다.

> **② 터치 한 번에 이벤트가 두 개 옵니다.**
> 프로젝트 설정의 `emulate_mouse_from_touch` 가 기본으로 켜져 있어서,
> 손가락 한 번에 `InputEventScreenTouch` 와 `InputEventMouseButton` 이
> **둘 다** 날아옵니다. 양쪽을 다 처리하면 리듬 게임에서 한 번 탭에
> 노트가 두 개 사라집니다.
> 그래서 이 프로젝트는 **마우스 이벤트만** 봅니다. 새 화면을 만들 때도
> 같은 규칙을 지키세요.

### 아직 안 한 것

- **세로로 들면 화면이 좁아집니다.** 가로로 돌려 달라는 안내가 없습니다.
  (웹은 화면 회전을 강제할 수 없어서, HTML 껍데기에 안내를 넣거나
  세로일 때 "가로로 돌려주세요"를 띄우는 방법뿐입니다)
- 로딩 화면 꾸미기 (지금은 Godot 기본 껍데기)
